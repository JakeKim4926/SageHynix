# rehearse-explanation

끝나면 사용자가 자기 말로 답해 본 기록과, 틀리거나 빠진 점에 대한 피드백이 `docs/COGNITION.md`에 남아 있다. 후속 서술형은 제출물과 작업 기록에서 출제되므로, AI가 만든 것을 사람이 설명하지 못하면 그것이 인지 부채다.

## 입력
- **슬라이스 모드**: 방금 끝낸 슬라이스의 코드, VERIFICATION 행, 관련 D-n.
- **제출 모드**: `git log --oneline`, `git diff --stat {첫 커밋}..HEAD`, docs/INTENT·PLAN·DECISIONS·VERIFICATION·COGNITION, 제출 문서, 미검증 항목과 A-n.

## 진행
**슬라이스 모드**
1. 코드를 다시 읽고 `docs/COGNITION.md`에 설명 카드(10줄 이내)를 추가한다: 한 줄 요약, 데이터 흐름(입력 파일 → 파일:함수 → 출력), 핵심 판단 1~2개와 이유(D-n), 대표 수치와 의미(VERIFICATION 출처), 실패 모드.
2. 셀프 퀴즈 3문항을 답 없이 낸다: **왜**(대안 대비 이 방법을 택한 이유), **어떻게**(특정 수치가 어떤 계산으로 나오나, 코드 위치까지), **만약**(데이터나 요구가 바뀌면 무엇이 깨지고 어떻게 대응하나).

**제출 모드**: [references/defense.md](references/defense.md)를 읽고 질문 8~10개와 답변 골격을 만들어 COGNITION.md "예상 후속 질문"에 추가한다.

**채점 (두 모드 공통)**: 사용자에게 가장 약한 문항(제출 모드는 3개)에 직접 짧게 답해 달라고 요청한다. 답이 오면 맞은 점과, 틀리거나 빠진 점을 코드·문서 근거로 짚는다. 정답을 대신 길게 쓰지 않고 빠진 핵심 키워드와 확인할 파일 위치만 준다.

## 제약
- 카드와 질문은 실제 코드와 일치해야 한다. 기억으로 쓰지 않는다.
- 약점을 강점으로 포장하지 않는다.
- 사용자가 이해하지 못한 원인이 불필요하게 복잡한 코드라면 단순화를 제안한다. 설명할 수 없는 코드는 제출 리스크다.

## 완료 기준
- 사용자가 답했고 채점이 끝났다. 시간이 없어 건너뛰었다면 건너뛴 사실이 카드에 표시돼 있다.

## 출력
- 슬라이스 모드: 카드와 퀴즈, 이후 채점 결과.
- 제출 모드: 질문과 골격, 외워야 할 앵커(숫자, 파일명, 결정 ID) 10개 목록.
- 커밋: `docs(cognition): S2 설명 카드 — 수율 계산 기준`
