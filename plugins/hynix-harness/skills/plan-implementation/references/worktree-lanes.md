# 병렬 구현 레인 (git worktree)

여러 터미널의 Codex 세션이 서로 다른 파일을 병렬로 구현하고 메인에 병합한다. 레인은 최대 2~3개. 세션 수만큼 토큰과 응답 대기도 늘어난다.

## 진행
1. **인터페이스 먼저**: 레인 사이 계약(함수 시그니처, 데이터 파일 스키마, API 응답 예시)을 `docs/PLAN.md`에 쓰고 커밋한다. 가능하면 스텁 코드까지 커밋한다. 레인은 커밋된 하네스 파일만 받는다.
2. **레인 생성** (메인 작업 공간에서): `.harness/bin/wt.sh new {lane}` → `~/wt/{lane}`에 브랜치 `lane/{lane}`이 생긴다.
3. **레인 실행**: 웹 IDE 터미널 `+`로 새 탭을 열고 `cd ~/wt/{lane} && codex`. 첫 지시에 레인 범위, 건드리면 안 되는 파일, 계약 위치, 완료 기준을 준다. 서버를 띄우면 레인마다 다른 포트를 쓴다.
4. **레인 종료**: 레인 안에서 `.harness/bin/verify.sh` 통과 후 커밋.
5. **병합** (메인에서 하나씩): `.harness/bin/wt.sh merge {lane} && .harness/bin/verify.sh`. 충돌은 사람이 확인하며 해결하고, 해결 내용을 커밋 메시지에 남긴다.
6. **정리**: `.harness/bin/wt.sh rm {lane}`. WORKLOG에 레인별 결과를 적는다.

## 제약
- 레인 worktree는 작업 공간 밖(`~/wt/`)에 있어 병합 전에는 제출물에 들어가지 않는다. 종료 30분 전까지 모두 병합한다.
