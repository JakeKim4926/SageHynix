# Doc Review

## 체크리스트 (항목마다 실제로 확인하고 결과를 표로)
1. **필수 산출물**: INTENT의 산출물 표 vs `ls`/`git ls-files` — 경로·파일명 철자까지 일치? 빈 파일 없음?
2. **커밋 상태**: `git status --porcelain`이 비어 있는가(작업 공간 파일이 제출되지만 기록 일관성을 위해). 에디터 탭의 "저장됨" 확인은 사용자에게 요청.
3. **주장-근거 대조**: 문서의 수치·"완료"·"검증" 문장을 모두 뽑아 VERIFICATION/verify.log/코드와 대조. 불일치는 `문서:줄 → 실제 → 수정 문구`.
4. **추적성**: R-n마다 PLAN → 코드 위치 → VERIFICATION 행이 있는가. 끊긴 것은 "구현 안 됨/검증 안 됨"으로 문서에 반영.
5. **실행 방법 재현**: README의 실행 명령을 실제로 실행(서버면 띄우고 curl로 응답 확인 후 종료).
6. **한계 섹션**: 미검증 항목, A-n 가정, 제외 범위가 모두 들어갔나.
7. **표현**: "완벽/모든/최적/보장" 등 과장, 근거 없는 일반론, AI 말투 반복 제거.
8. **민감 정보**: 키·토큰·개인 정보가 문서·코드·로그에 없는가 (`rg -n -i "api[_-]?key|token|secret|password"`).

## 실행 방식
- 문서가 많거나 시간이 부족하면 `doc_auditor` 서브에이전트에 1·3·4번을 맡기고, 메인은 2·5·8번을 직접 실행한다(병렬).
- 결과는 수정 목록으로 사용자에게 보여 주고, 승인된 것만 `$doc-writer` 수정 모드로 반영한다.
