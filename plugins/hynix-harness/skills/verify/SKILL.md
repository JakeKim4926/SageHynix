# Verify

"완료"는 주장이 아니라 증거다.

## 절차
1. **주장 목록**: 이번 작업이 충족한다고 주장하는 요구사항 R-n을 `docs/research/task.md`에서 가져온다.
2. **자동 검증**: `.harness/bin/verify.sh` — 문법, 오류급 lint, pytest. FAIL이면 고치고 다시. "tests/ 없음"이면 핵심 계산에 최소 테스트를 추가한다(손으로 계산 가능한 작은 입력, 빈 데이터·결측·중복 키).
3. **요구사항별 검증** — 기준마다 실제 명령을 실행한다.
   - 수치: 다른 경로로 다시 계산해 일치 확인(예: pandas 집계 vs 순수 파이썬 합계)
   - 웹: `0.0.0.0:<port>`로 떠 있는지, `curl -s http://127.0.0.1:<port>/<path>` 응답 확인. 화면은 사용자에게 Browser 탭(PORT/경로) 확인을 요청한다
   - 성능 요구가 있으면 실제 데이터 전체로 1회 시간 측정
4. **기록**: `docs/VERIFICATION.md` 표에 행 추가 — 요구사항 | 구현 위치 | 명령 | 관찰 결과 | 시각. 실패·미실행도 그대로 적는다.
5. **커밋** (통과한 것만): `git add -A && git commit -m "feat(<scope>): <무엇> — <R-n 충족>, verify PASS"`
6. **사람용 3줄**: 무엇이 동작하나 / 대표 수치 하나와 그 계산 경로(파일:함수) / 알려진 실패 모드. 사용자가 AI 없이 설명할 수 있어야 한다.

## 독립 검증 (중요 수치, 제출 전)
`verifier` 서브에이전트에 `prompts/SCRIPT.md`의 6칸 형식으로 맡긴다. [Context]에 주장 목록과 실행 방법, [Done]에 "모든 주장에 통과/실패/검증불가 판정"을 적는다. 결과는 그대로 VERIFICATION.md에 옮긴다.

## 금지
- 실행하지 않고 "통과"라고 쓰기
- 실패 테스트를 지우거나 skip해서 통과시키기, 기대값을 결과에 맞춰 고치기
