# Verify Gate

"완료"는 주장이 아니라 증거다. (Technique 축 / 기술 부채 방지)

## 절차
1. **주장 목록화**: 이번 슬라이스가 충족한다고 주장하는 수용 기준(R-n)을 PLAN에서 가져온다.
2. **자동 검증**: `.harness/bin/verify.sh` — 문법, 오류급 lint, pytest. FAIL이면 고친 뒤 다시. SKIP이 "tests/ 없음"이면 핵심 계산에 최소 테스트를 추가한다:
   - 손으로 계산 가능한 작은 입력 → 기대값 비교
   - 경계: 빈 데이터, 결측, 중복 키
3. **수용 기준별 검증**: 기준마다 실제 명령을 실행한다.
   - 수치: 독립 경로로 재계산(예: pandas 집계 vs 순수 파이썬 합계)해서 일치 확인
   - 웹: 서버가 `0.0.0.0:<port>`로 떠 있는지, `curl -s http://127.0.0.1:<port>/<path>`로 응답 확인. 화면 동작은 사용자에게 Browser 탭(PORT/경로)에서 확인을 요청하고 결과를 받는다.
   - 성능·규모 요구가 있으면 실제 데이터 전체로 1회 실행 시간 측정
4. **기록**: `docs/VERIFICATION.md` 추적 표에 행 추가 — 요구사항 | 구현 위치(파일:함수) | 명령 | 관찰 결과 | 시각. 실패·미실행은 그대로 적는다.
5. **커밋** (통과한 것만):
   ```bash
   git add -A && git commit -m "feat(<scope>): <무엇> — <R-n 충족>, verify PASS"
   ```
   커밋 단위가 크면 나눈다. 디버그용 임시 파일은 커밋하지 않는다.
6. 슬라이스 결과를 ctx에 남긴다: `ctx.py new slice <s-n> --q "<슬라이스 목표>" --serves R-n --inputs <핵심 파일>` → `slice.md`(한 일·검증) → `ctx.py done slice/<s-n>`.
7. 다음은 `$cognition-check`.

## 금지
- 실행하지 않고 "통과"라고 쓰기, 실패 테스트를 지우거나 skip 처리해서 통과시키기, 기대값을 결과에 맞춰 고치기(고쳐야 한다면 이유를 DECISIONS에).
- 독립 검증이 필요하면(중요 수치, 제출 직전) `verifier` 서브에이전트에게 맡기고 결과를 그대로 기록한다.
