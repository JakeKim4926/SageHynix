# SCRIPT — 6칸 지시 형식

사람→Codex, Codex→서브에이전트, 세션→다음 세션으로 일을 넘길 때 모두 이 형식을 쓴다.
받는 쪽은 보내는 쪽의 대화를 모른다. 넘어가는 것은 이 6칸뿐이다.

```
[Role]    누구로서 일하나 — 관점과 권한 (예: 읽기 전용 조사자, 코드 수정 금지)
[Context] 이미 아는 것 — 사실, 파일 경로, 정해진 결정, 담당자 답변. "위에서 말한"처럼 대화를 가리키지 않는다
[Task]    할 일 하나 — 동사로 시작, 이 결과로 무엇을 결정하는지
[Rules]   하지 말 것·범위 밖·규정 (외부 전송 금지, README 우선, 수치는 실행 결과만)
[Output]  돌려줄 것 — 파일 경로와 형식, 보고 길이
[Done]    끝 조건 — 확인 가능한 문장 (예: 4섹션이 모두 채워짐, verify.sh PASS)
```

## 이 형식이 막는 네 가지 유실

| 유실 | 일어나는 일 | 막는 칸 |
|---|---|---|
| 목적 유실 | 왜 하는지 몰라 엉뚱한 쪽을 최적화한다 | [Role] [Task] |
| 맥락 유실 | 이미 확인한 사실·결정이 안 넘어가 재조사하거나 모순된 결과를 낸다 | [Context] |
| 제약 유실 | 앞에서 말한 금지·범위가 긴 대화 속에서 희석된다 | [Rules] |
| 완료 유실 | 언제 끝인지, 무엇을 돌려줘야 하는지 몰라 과잉·미완·형식 불일치가 난다 | [Output] [Done] |

빈 칸이 있으면 보내지 않는다. 모르는 칸은 "없음"이라고 쓴다.

---

## 복사용 스크립트 (`<…>`만 채운다)

### S1. 과제 파악 — 시작 직후
```
[Role] 이 작업 공간의 조사 담당. 이 단계에서는 코드를 쓰지 않는다.
[Context] 과제 안내는 README.md. 제공 파일: <ls 결과 또는 "README 참고">.
[Task] $research 로 과제를 파악해 필수 산출물·요구사항(R-n)·제약을 정리하고, 업무 담당자에게 물을 질문을 만든다.
[Rules] README에 없는 요구사항을 만들지 않는다. 추론은 '추론'으로 표시. 데이터 파일은 크기만 보고 내용은 다음 단계에서.
[Output] docs/research/task.md (4섹션). 채팅에는 요구사항 5줄 요약 + 담당자에게 보낼 질문 한 블록.
[Done] task.md의 결론에 필수 산출물 표와 R-n 목록이 있고, 질문이 우선순위 순 3~5개.
```

### S2. 조사 위임 — Codex → researcher 서브에이전트
```
[Role] researcher. 읽기·작은 실험만, 프로젝트 코드는 수정하지 않는다.
[Context] 과제 요약: <task.md 결론 3줄>. 관련 파일: <경로>. 이미 정해진 것: <결정>.
[Task] <질문 하나>. 이 답으로 <무엇을> 결정한다.
[Rules] 출처 없는 주장은 '미확인'. 수치는 실행한 것만. 범위 밖: <…>.
[Output] docs/research/<주제>.md 한 파일 (결론/근거/미확인/담당자 질문). 채팅에는 결론 첫 줄만.
[Done] 4섹션이 모두 채워지고 결론의 각 문장에 근거 항목이 있다.
```

### S3. 구현 요청
```
[Role] 구현 담당. 한 번에 이 기능 하나만.
[Context] 요구사항: <R-n과 수용 기준>. 근거: docs/research/<…>.md. 관련 코드: <파일>.
[Task] <기능>을 데이터→로직→출력까지 작동하게 만든다.
[Rules] 범위 밖: <…>. 새 패키지는 설치 전 import 확인. 서버는 0.0.0.0. git push·외부 전송 금지.
[Output] 변경 파일 목록, 실행 명령, 결과 요약.
[Done] $verify 통과 + docs/VERIFICATION.md에 행 추가 + 커밋.
```

### S4. 검증 위임 — Codex → verifier 서브에이전트
```
[Role] verifier. 구현자의 주장을 믿지 않고 직접 실행한다. 코드는 수정하지 않는다.
[Context] 주장 목록: <R-n: 주장>. 실행 방법: <명령, 포트>.
[Task] 주장마다 실제 명령으로 확인한다.
[Rules] 실행 못 한 것은 '검증불가'. 실패를 줄여서 보고하지 않는다.
[Output] 표: 주장 | 실행한 명령 | 관찰 결과 | 통과/실패/검증불가.
[Done] 모든 주장에 판정이 있다.
```

### S5. 문서 작성·감사
```
[Role] 제출 문서 담당.
[Context] 필수 산출물: docs/research/task.md. 검증 기록: docs/VERIFICATION.md. 판단 근거: docs/research/*.md.
[Task] $doc 으로 <문서명>을 작성한다 (또는: 제출 전 감사 / 서술형 대비).
[Rules] 과제 지정 양식 우선. 재현 명령 없는 수치 금지. 한계 섹션 필수. 과장 표현 금지.
[Output] <파일 경로>. 채팅에는 바뀐 섹션 목록.
[Done] 모든 사실 문장에 출처가 있고, 감사 체크리스트 6항목 결과가 표로 있다.
```

### S6. 세션 인수인계 — 새 세션을 열 때
```
[Role] 이전 세션의 작업을 이어받는 담당.
[Context] 읽을 것: docs/research/task.md, docs/VERIFICATION.md, git log --oneline -10. 현재 상태: <한 줄>. 막힌 것: <한 줄>.
[Task] <다음 할 일 하나>.
[Rules] 이미 있는 docs/research 결과는 다시 조사하지 않는다. AGENTS.md 절대 규칙 유지.
[Output] <…>
[Done] <…>
```
