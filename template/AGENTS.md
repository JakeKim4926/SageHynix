# AGENTS.md — SK하이닉스 AI 해커톤 하네스

180분 안에 "데이터를 활용한 AI 문제 해결 미션"을 푸는 작업 공간이다.
평가는 결과물과 과정(대화·터미널·git log/diff·테스트 결과·문서)을 함께 본다. 코드를 많이 쓰는 것보다 **검증된 결과와 설명 가능한 판단**이 목표다.

## 1. 절대 규칙
1. **거짓 보고 금지.** 실행하지 않은 명령, 확인하지 않은 수치, 통과하지 않은 테스트를 "완료/통과"라고 쓰지 않는다. 확인 못 한 것은 `미검증`.
2. **애매하면 묻는다.** 요구사항·데이터 의미·성공 기준이 둘 이상으로 해석되면 추측으로 구현하지 말고 사용자에게 묻거나 "담당자 질문"을 만든다. 가정으로 진행했다면 그 사실을 남긴다.
3. **과제 README가 최우선.** 필수 파일명·산출물·형식은 README를 따른다.
4. **외부 전송 금지.** `git push`, 외부 업로드(curl -F/-T/--data 등), scp/ssh/nc 금지. 공개 저장소 clone과 패키지 설치는 허용.
5. **플랫폼 설정 불가침.** `~/.codex/config.toml`, 감독·연결 프로세스, 키·토큰을 수정·종료·출력하지 않는다. `.codex/hooks*`, `.codex/rules/`도 수정하지 않는다.
6. **모델:** Astra 계열은 사용 제한. 권장 Sol 6.1 / Terra 5.6 / Luna 6 / Sol 6.0.
7. **웹 서버는 `0.0.0.0`에 바인딩**하고 포트를 출력한다. 서버 터미널은 닫지 않는다.
8. **개인 API 키 사용 금지.** 과제가 제공하지 않은 외부 LLM API를 코드에서 호출하지 않는다.

## 2. 흐름과 skill (이 3개만 쓴다)
| 시각 | 할 일 | skill | 남는 파일 |
|---|---|---|---|
| 0–30분 | 과제·데이터·기법 조사, 담당자 질문 | `$research` | `docs/research/<주제>.md` |
| 30–140분 | 기능 하나씩 구현 → 검증 → 커밋 | `$verify` | 코드, 테스트, `docs/VERIFICATION.md` |
| 140–170분 | 제출 문서, 감사, 서술형 대비 | `$doc` | 과제 지정 문서 |
| 170분 | 제출 시작 | — | — |

- 한 번에 기능 하나. "완료"라고 말하기 전에 반드시 `$verify`.
- 시간이 밀리면 범위를 줄이고, 뺀 것과 이유를 문서의 한계 섹션에 남긴다.
- 새 조사 전 `ls docs/research/` — 있는 결과는 재사용한다.

## 3. 일을 넘길 때는 6칸 SCRIPT (`prompts/SCRIPT.md`)
서브에이전트에게 맡길 때, 새 세션을 열 때, 긴 작업을 지시할 때 이 형식을 쓴다. 받는 쪽은 이 대화를 모른다.
```
[Role] [Context] [Task] [Rules] [Output] [Done]
```
- [Context]에 사실·파일 경로·정해진 결정을 직접 적는다("위에서 말한" 금지).
- 빈 칸이 있으면 보내지 않는다. 모르면 "없음".
- 서브에이전트: `researcher`(조사, 최대 3개 병렬), `verifier`(독립 검증). 둘 다 코드 수정 금지. 서로 독립인 질문만 병렬로.

## 4. 기술 기본값
- pandas/numpy. 대시보드면 Streamlit, API·커스텀 화면이면 FastAPI. README가 다르면 README.
- 설치 전 `python3 -c "import X"`로 확인. 의존성은 `requirements.txt`.
- 숫자 결과는 재현 명령과 함께. 무작위성은 seed 고정. 테스트는 `tests/`에 pytest.

## 5. 커밋 (git log도 평가 대상)
- 기능·의미 단위. `<type>(<scope>): <무엇을> — <왜>` (예: `feat(etl): 결측 웨이퍼 ID 제거 — R-2 수율 왜곡 방지`)
- `git reset --hard`, 히스토리 재작성, 제출 직전 통째 교체 금지.
