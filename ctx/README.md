# ctx/ — 작업 기억 저장소

조사·분석·결정·프롬프트를 한 번 하면 여기에 남기고, 다음 세션·다른 레인·다른 터미널에서 **다시 하지 않고 이어 쓴다**.
`docs/`는 제출·평가용 문서, `ctx/`는 작업 중 기억이다. `docs/`는 근거로 `ctx/` ID를 인용한다.

## 먼저 볼 것
- `INDEX.md` — 항목당 한 줄(ID · 상태 · 한 줄 요약). 자동 생성, 직접 고치지 않는다.
- 상세는 필요한 항목만: `python3 .harness/bin/ctx.py get research/anomaly`

## 폴더
| 경로 | 무엇 | 본문 파일 (필수 섹션) |
|---|---|---|
| `research/<주제>/` | 조사 하나 | `brief.md` 지시서, `report.md` (결론·근거·미확인) |
| `data/<데이터셋>/` | 데이터 프로파일 | `profile.md` 스크립트 출력, `notes.md` (컬럼 의미·함정·분석 영향) |
| `decision/<주제>/` | 선택과 근거 대조 | `decision.md` (결정·버린 대안·근거 대조) |
| `slice/<S-n>/` | 구현 단위 결과 | `slice.md` (한 일·검증) |
| `prompt/<용도>/` | 잘 먹힌 프롬프트 | `prompt.md` (언제 쓰나·프롬프트) |
| `session/<시각>/` | 세션 인수인계 스냅숏 | `handoff.md` (현재 상태·다음 단계) |
| `note/<주제>/` | 그 밖의 기억할 것 | `note.md` (내용) |

## 상태
| 상태 | 뜻 | 쓰는 법 |
|---|---|---|
| `draft` | 작성 중 | 이어서 쓰고 `done` |
| `valid` | 검증된 본문, 입력 그대로 | **재사용. 같은 조사·질문을 다시 하지 않는다** |
| `stale` | 입력 파일이 바뀌었거나 의존 항목이 다시 작성됨 | 그대로 근거로 쓰지 않는다. `new … --redo` 또는 확인 |
| `superseded` | 다른 항목으로 대체 | `by`가 가리키는 항목을 쓴다 |

## 규칙
- `index.jsonl`(메타데이터 원장)은 `ctx.py`만 쓴다. 직접 편집은 훅이 막는다.
- 모델은 본문 Markdown만 쓴다. `done`은 필수 섹션이 비어 있으면 거부한다.
- `--inputs`에 건 파일(데이터, README 등)이 바뀌면 자동으로 `stale`이 된다. `--uses`로 건 항목이 다시 작성돼도 `stale`.
