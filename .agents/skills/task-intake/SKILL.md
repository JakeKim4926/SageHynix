# Task Intake

목표: 코드를 한 줄도 쓰기 전에 **무엇을, 누구를 위해, 어떤 기준으로** 만들지 문서로 고정한다. (Intent 축)

## 절차

1. **자료 목록화**: `ls -la`, `find . -maxdepth 3 -not -path './.git*' -not -path './.agents*' -not -path './.codex*' -not -path './.harness*'`로 제공 파일 전체를 본다. 데이터 파일은 크기만 확인하고 내용은 `$data-profile`에 넘긴다.
2. **README 정독**: 전체를 읽고 다음을 줄 번호와 함께 뽑는다.
   - 필수 산출물(파일명·경로·형식) — 하네스 기본 문서명보다 **우선**
   - 기능 요구사항, 비기능 요구사항(성능·실행 방법·포트 등)
   - 제약(사용 금지 기술, 데이터 사용 범위, 시간)
   - 평가/채점 언급
3. **docs/INTENT.md 작성**: 요구사항마다 ID(R-n), 측정 가능한 수용 기준, 출처를 단다. 수용 기준을 숫자·관찰 가능한 행동으로 못 쓰겠으면 그 자체가 질문(Q-n)이다.
4. **애매함 목록 → 질문**: 해석이 둘 이상 가능한 곳마다 Q-n을 만든다. 각 질문은
   - 업무 담당자가 한 문장으로 답할 수 있게 (예/아니오, 선택지 제시)
   - 답에 따라 무엇이 바뀌는지 함께 적는다.
   우선순위가 높은 3~5개만 먼저 묻도록 정렬한다.
5. **사용자에게 보고**: 요구사항 요약(5줄 이내), 필수 산출물 표, 업무 담당자에게 보낼 질문 메시지(복사해서 메신저에 붙여 넣을 수 있는 형태), 답을 기다리는 동안 진행할 수 있는 일.

## 규칙
- README에 없는 요구사항을 만들어 넣지 않는다. 추론한 것은 출처를 `추론`으로 표시한다.
- 답을 못 받은 채 진행해야 하면 가정 A-n을 기록하고 되돌리기 쉬운 쪽을 택한다.
- 이 단계에서 구현·패키지 설치를 하지 않는다.
- 커밋: `docs(intent): 요구사항 원장 초안 — README 기준 R-1..R-n`
