# Research

다음 세션·서브에이전트는 대화를 모른다. 결과는 파일로만 넘어간다.
시작 전에 `ls docs/research/`와 `docs/INTENT.md`를 본다. 같은 주제 파일이 있으면 읽고 재사용한다 — 같은 조사·같은 질문을 다시 하지 않는다.

## 주제별 할 일
| 주제 | 방법 | 결과 |
|---|---|---|
| 과제 | 과제 README·제공 자료 정독. 필수 산출물(파일명·형식), 요구사항 R-n과 측정 가능한 수용 기준, 제약, 평가 언급을 줄 번호와 함께. 해석이 둘 이상이면 Q-n | `docs/INTENT.md` |
| 담당자 답변 | 사용자가 붙여 넣은 대화에서 새 요구사항·성공 기준·데이터 의미·"모른다"를 원문 1줄과 함께 추출. Q-n 상태를 `답변됨 → R-x/A-y`로, 바뀐 R-n은 변경 이력에 | `docs/INTENT.md` |
| 데이터 | `python3 .agents/skills/research/scripts/profile_data.py <파일...>` 실행 → 컬럼 의미, 키·조인 매칭률, 함정(누수·시간 순서·단위·중복·불균형) | `docs/research/data-<이름>.md` |
| 도메인·기법 | 용어의 과제 내 의미, 후보 접근 2~3개(구현 시간·설명 가능성·실패 모드), 추천 1개 | `docs/research/<주제>.md` |

큰 데이터는 `--max-rows 200000`으로 표본 프로파일링하고 표본이라고 적는다.

## docs/research/<주제>.md 형식 (4섹션 고정)
```markdown
# <주제>
## 결론      — 결정에 쓰일 것만 3줄
## 근거      — 사실마다 출처: 파일:줄 / 실행 명령과 결과 / URL
## 미확인    — 모르는 것. 추정은 '추정'이라고 쓴다
## 담당자 질문 — 예/아니오·선택지형, 답에 따라 바뀌는 것 함께, 우선순위 순
```

## 병렬 (독립 질문 2개 이상일 때만)
- `researcher` 서브에이전트 최대 3개. 지시는 `prompts/SCRIPT.md`의 6칸 `[Role] [Context] [Task] [Rules] [Output] [Done]`으로 쓴다(S2).
  서브에이전트는 이 대화를 모른다 — 필요한 사실과 파일 경로를 [Context]에 직접 적는다.
- 서로의 결과에 의존하는 질문은 순차로. 이미 답이 있는 질문(README, INTENT, 기존 research 파일)은 맡기지 않는다. 토큰 사용량도 평가 신호다.
- 끝나면 메인이 결론을 합쳐 보고하고, 서브에이전트가 낸 수치 하나 이상은 직접 다시 실행해 확인한다. 서로 충돌하는 주장은 충돌로 적는다.

## 규칙
- 수치는 실행 결과에서만 쓴다. 원본 데이터는 수정하지 않는다.
- README에 없는 요구사항을 만들지 않는다. 추론한 것은 `추론`으로 표시한다. 담당자가 말하지 않은 것을 말했다고 쓰지 않는다.
- README와 담당자 답이 충돌하면 둘 다 기록하고 사용자에게 어느 쪽을 따를지 묻는다.
- 답을 못 받은 채 진행해야 하면 INTENT에 가정 A-n을 기록하고 되돌리기 쉬운 쪽을 택한다.
- 담당자 질문은 우선순위 3~5개만, 사용자가 메신저에 그대로 붙여 넣을 수 있게 한 블록으로 준다. 담당자에게는 SCRIPT 형식이 아니라 자연어로 묻는다.
- 이 단계에서는 구현하지 않는다.
- 커밋: `docs(research): <주제> — <결론 한 줄>` / `docs(intent): 담당자 답변 반영 — Q-2→R-4`
