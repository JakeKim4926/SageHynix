# Stakeholder Sync

업무 담당자는 과제의 "고객"이다. 대화는 기록되고, 합의된 내용이 구현에 반영됐는지가 Intent 평가의 핵심이다.

## 입력
- 사용자가 붙여 넣은 대화(또는 요약). 없으면 먼저 요청한다: "담당자 대화를 붙여 넣어 주세요."

## 절차
1. 대화에서 다음을 추출한다(원문 인용 1줄과 함께):
   - 새 요구사항 / 기존 요구사항의 변경·구체화
   - 성공 기준·우선순위·범위에 대한 답
   - 데이터 의미(컬럼, 코드값, 단위, 기간)에 대한 답
   - 담당자가 **모른다/정하지 않았다**고 한 것 → 가정으로 처리할 후보
2. `docs/INTENT.md` 갱신:
   - Q-n 상태를 `답변됨 → R-x/A-y 반영`으로 바꾼다.
   - 변경된 R-n은 이전 내용을 지우지 말고 변경 이력 표에 남긴다.
3. **영향 분석**: 이미 구현·계획된 것 중 바뀌어야 하는 것(PLAN 슬라이스, 코드 파일)을 나열한다.
4. **다음 질문**: 아직 남은 고위험 애매함이 있으면 다음 메시지 초안을 만든다. 질문은 최대 3개, 선택지 포함.
5. 담당자 답변 원문은 `ctx.py new note stakeholder-<주제> --q "<무엇을 물었나>"`로 남긴다(같은 질문을 다시 보내지 않도록). 보내기 전에 `ctx.py find`로 이미 물은 질문인지 확인한다.
6. 보고: 반영 내역 표, 영향받는 작업, 다음 질문 초안.

## 규칙
- 담당자가 말하지 않은 것을 말했다고 쓰지 않는다. 해석이 들어가면 `해석:`으로 구분한다.
- README와 담당자 답이 충돌하면 둘 다 기록하고 사용자에게 어느 쪽을 따를지 묻는다.
- 커밋: `docs(intent): 담당자 답변 반영 — Q-2→R-4, A-1 확정`
