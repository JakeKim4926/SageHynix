# FE 환경 준비와 복구

## 기존 프로젝트 우선

- 앱 루트, package.json의 scripts·engines·packageManager, lockfile을 읽는다. 기존 npm/pnpm/yarn 선택을 유지하며 여러 lockfile을 만들지 않는다.
- Node와 해당 패키지 매니저의 경로·버전·실제 실행을 확인한다. 명령 존재만으로 정상 판정하지 않는다.
- Node 호환성은 설치할 패키지 버전의 공식 요구사항으로 확인한다. 지원하지 않는 Node에 최신 도구를 강제로 설치하지 않는다.
- Node가 없으면 플랫폼의 설치 방법·권한을 확인한다. 플랫폼 제공 Codex나 전역 설정을 교체하지 않는다.

## 설치

- 설치된 의존성이 정상 동작하면 재설치하지 않는다. 깨끗한 npm 재현 설치에 lockfile이 있으면 `npm ci`, 최초 생성이나 의존성 변경은 `npm install`로 lockfile을 함께 관리한다. `npm ci`는 기존 node_modules를 다시 구성하므로 매 수정마다 실행하지 않는다.
- 신규 앱은 빈 대상 폴더인지 확인하고 과제 중 생성한다. 기존 과제 파일을 덮어쓰지 않는다. 생성 도구와 라이브러리 버전을 확인·기록하고, 이후 작업에서는 lockfile을 유지한다.
- create-vite 9의 react-ts 템플릿은 린터가 ESLint가 아닌 oxlint이고 TypeScript 7이다. TypeScript 6 이상은 `strict`가 기본값이라 tsconfig에 표기가 없어도 켜져 있다. 템플릿 구성을 다른 도구로 바꾸지 않는다.
- Tailwind의 설치 방식은 선택한 메이저 버전의 공식 문서를 따른다. 서로 다른 버전의 플러그인·CSS 진입점·설정 예제를 섞지 않는다.
- 기본 준비에 차트·라우터·전역 상태·복잡한 표 라이브러리를 모두 설치하지 않는다. 요구사항과 기존 의존성을 보고 추가한다.
- 테스트 기본 도구는 Vitest·Testing Library·jsdom이다. Playwright는 기본 설치하지 않는다(브라우저 바이너리 약 720MB, 시험 환경 다운로드 미확인). 과제가 E2E를 요구할 때만 설치하며, 패키지와 브라우저 바이너리·OS 의존성은 별개다.

## 실패 분기

| 관찰 | 다음 행동 |
|---|---|
| 버전 불일치 | 플랫폼에서 지원하는 런타임과 패키지의 호환 조합 확인 |
| 네트워크·레지스트리 실패 | 오류와 접근 가능한 설치 경로 확인; 같은 명령 무한 재시도 금지 |
| 설치 권한 실패 | 허용된 프로젝트 설치 경로 확인; 전역 권한 변경 금지 |
| lockfile 불일치 | 변경된 의존성을 확인하고 의도된 변경일 때만 lockfile 갱신 |
| 브라우저 실행 불가 | 사용 가능한 Browser 도구로 확인; 그것도 없으면 사용자 확인과 미검증 기록 |

패키지 설치 성공, 빌드 성공, 브라우저 동작 성공은 각각 기록한다.
