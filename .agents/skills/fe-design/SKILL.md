# FE Design

목표: 디자인 고민 없이 SK 톤의 일관된 화면을 만든다. 디자인은 기능 위의 얇은 층이며 기능·검증보다 앞세우지 않는다.

1. 과제 안내나 기존 앱의 스타일 규칙이 있으면 그것을 따른다. 없으면 [sk-tokens.md](references/sk-tokens.md)의 토큰을 앱 진입 CSS 한 곳(Tailwind v4는 `@theme`)에 정의한다. 컴포넌트에 HEX 값을 직접 쓰지 않는다. 같은 작업에서 이미 정의했다면 재독·재정의하지 않는다.
2. 화면 골격은 고정한다: 흰 상단 바(오렌지→레드 세로 막대 + 서비스명, 회색 하단선) → 회색 배경 위 흰 카드 → KPI 카드, 필터, 차트·표 순서. 디자인만을 위해 UI 라이브러리·아이콘 팩·웹폰트를 설치하지 않는다.
3. 색은 역할로만 쓴다. 컴포넌트 색은 [sk-tokens.md 컴포넌트별 색](references/sk-tokens.md)을 따르고, 표에 없으면 가장 가까운 행을 따른다. 색을 사용자에게 다시 묻거나 새 HEX를 만들지 않는다.
   - 화면 틀(상단 바·탭·필터·버튼)의 유채색은 action 하나다. 레드·오렌지는 서비스명 막대에만 두고, 활성 탭은 ink 막대로 표시한다.
   - 브랜드 레드: 서비스명 막대와 차트 하이라이트 1개에만 쓴다. 버튼·탭·링크·포커스·오류에 쓰지 않는다(danger와 구분되지 않음).
   - action(SK Blue): 강조 버튼 1종, 본문 링크, 선택 상태, 포커스 링.
   - 오렌지: 서비스명 막대·차트 계열·아이콘 등 그래픽에만 쓴다. 흰 배경 위 글자색으로 쓰지 않는다(대비 2.8:1).
   - 오류·불량·경고: 상태 토큰을 아이콘·문구와 함께 쓴다. 색만으로 상태를 전달하지 않는다. KPI 증감은 오르내림이 아니라 좋고 나쁨으로 칠한다.
   - 차트: [sk-tokens.md 차트 절](references/sk-tokens.md)의 계열 순서·순차·발산 색을 따르고, 양호/불량처럼 의미가 있는 색은 범례에 적는다. 토큰을 이미 정의했어도 차트를 처음 만들 때는 이 절을 읽는다.
4. 로고: SK 행복날개 심볼을 직접 그리거나 생성하지 않는다. 주최 측이 제공한 로고 파일만 원본 비율로 쓰고, 없으면 서비스명 막대와 텍스트 서비스명만 둔다.
5. 확인은 [FE 검증 계약](../verify/references/frontend.md)의 화면 확인에 합친다: 데스크톱·좁은 화면, 키보드 포커스 표시, 토큰 밖 HEX 검색(`grep -rnE "#[0-9a-fA-F]{6}" <앱 src>`; 토큰 진입 CSS와 차트 계열 모듈의 정의는 제외하고 본다). 별도 디자인 검증 기록을 만들지 않는다.

디자인 변경은 화면에서 달라진 점과 확인 방법만 짧게 보고한다. 커밋·인지 점검은 상위 작업 흐름에서 한 번만 한다.
