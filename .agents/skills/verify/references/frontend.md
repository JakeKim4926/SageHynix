# FE 검증 계약

npm 기반 FE(React/Vite 등) 변경에만 적용한다. Streamlit 화면은 verify 기본 절차(pytest·Browser 화면)로 검증한다. 앱 루트·패키지 매니저·실행 scripts는 fe-setup 결과 또는 기존 프로젝트에서 확인한다. 아래 명령 이름은 신규 npm 앱의 권장 계약이며 기존 앱 명령을 임의 교체하지 않는다.

## 자동 검사

1. 타입 검사: 앱 소스가 포함되는 tsconfig로 검사한다. 프로젝트 references 구성에서 빈 루트만 검사하지 않도록 대상 파일을 확인한다. Vite 변환·빌드 자체는 타입 검사가 아니다.
2. 린트: 프로젝트 설정의 대상 파일을 검사한다. 통과시키려고 규칙을 끄거나 오류를 숨기지 않는다.
3. 빌드: 실제 앱의 빌드 명령으로 산출물을 만든다.
4. 계산·데이터 변환 로직을 바꿨다면 대표 입력과 경계값 테스트를 실행한다. 스타일 수정만으로 구현을 복제하는 테스트를 추가하지 않는다.

신규 npm 앱을 frontend/에 둔 경우의 명령 예:

```bash
npm --prefix frontend run typecheck
npm --prefix frontend run lint
npm --prefix frontend run build
```

위 명령은 프로젝트 루트에서 직접 실행한다. pnpm/yarn·모노레포는 해당 앱 명령으로 바꾼다.

검증 스크립트 누락·의존성 없음·브라우저 실행 불가는 미검증이다. `--if-present`, 테스트 0개, SKIP 또는 종료 코드 0만으로 필수 검증 통과를 주장하지 않는다. verify.local.sh가 없으면 필요한 FE 명령을 직접 실행하고 누락을 기록한다.

## 동작·화면 검사

- 수용 기준에 해당하는 입력→조회/실행→기대 결과를 실제 브라우저에서 확인한다.
- 실제 API 연동 1개 이상을 확인한다. mock 기반 상태 테스트와 구분한다.
- 변경에 관련된 로딩·빈 결과·실패·재시도·0/결측 표시를 확인한다.
- 화면 변경은 데스크톱·좁은 화면에서 주요 내용과 조작이 보이는지 확인한다. 키보드로 핵심 입력·버튼을 조작한다.
- 브라우저 자동화가 가능하면 기존 Playwright 또는 제공 도구를 사용한다. 자동화가 없으면 사용자에게 구체적인 경로·동작·기대값을 제시해 확인받는다. 응답이 없으면 미검증으로 남긴다.
- E2E 명령은 한 번 실행하고 종료하도록 한다. 기존 미리보기 서버는 유지하고 테스트가 만든 서버만 정리한다.

## 기록

docs/LOG.md 검증 표에 요구사항 | 앱 경로/변경 | 명령·브라우저 동작 | 관찰 결과 | 미검증을 기록한다. 코드 검증, 화면 확인, 업무 수치 검증을 혼동하지 않는다. 앱이 없는 하네스 문서 변경에서는 앱 테스트를 통과했다고 쓰지 않는다.
