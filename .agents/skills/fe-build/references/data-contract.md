# API와 수치 표시 계약

기존 INTENT·DECISIONS·API 타입에 있는 정의를 재사용한다. 중복 문서를 만들지 않는다.

구현 전에 필요한 항목: 요청 조건, 응답 필드와 타입, 단위, 결측 의미, 분모·집계 수준, 정렬·페이지 범위, 오류 응답. 불명확하면 담당자 질문 또는 명시적인 가정으로 남긴다.

- API 데이터는 경계에서 검증하고 내부 컴포넌트에는 확인된 타입을 전달한다.
- 업무 계산은 검증된 계산 계층 한 곳에 둔다. Python API가 필요한 과제라면 그 결과를 FE에서 다른 기준으로 재계산하지 않는다. FE만 있는 과제는 순수 계산 함수로 분리해 검증한다.
- 페이지 일부의 행으로 전체 합계를 계산하지 않는다. 평균·비율을 다시 평균내야 한다면 가중치와 분모를 확인한다.
- 단위(건, %, 초 등), 반올림 자리, 시간대, 적용 필터를 사용자에게 필요한 만큼 표시한다.
- 차트는 축·단위·범례를 표시하고 표와 같은 데이터 범위를 사용한다. 결측을 자동으로 0으로 채우지 않는다.
- 제공 데이터, 임시 fixture, 실제 API 중 어느 경로인지 구분한다. mock을 없앴다는 주장은 실제 연결로 확인한다.

검증 예: 작은 고정 입력의 기대 집계와 API 응답, 화면 표시값을 대조한다. UI 상태 검사는 mock으로 할 수 있지만 실제 API 연동 검증을 대신하지 못한다.
