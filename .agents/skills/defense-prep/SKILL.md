# Defense Prep

## 입력 수집
- `git log --oneline`, `git diff --stat <첫 커밋>..HEAD`
- docs/INTENT, PLAN, DECISIONS, VERIFICATION, COGNITION, 제출 문서
- 미검증 항목과 가정(A-n)

## 질문 생성 (8~10개, 유형별 최소 1개)
| 유형 | 예시 형태 |
|---|---|
| 의도 | "업무 담당자의 요구 X를 어떤 기준으로 해석했나? 다른 해석이면 무엇이 달라지나?" |
| 판단 | "D-n에서 B 대신 A를 고른 근거는? A의 약점은?" |
| 기술 | "<핵심 수치>는 어떤 계산으로 나오나? 결측/중복은 어떻게 처리했나?" |
| 검증 | "결과가 맞다는 걸 어떻게 확인했나? 무엇이 미검증인가?" |
| 실패 | "데이터가 N배/새 설비 추가/형식 변경 시 무엇이 깨지나?" |
| AI 활용 | "AI 결과를 그대로 쓰지 않고 고친 사례는? 왜?" |
| 개선 | "시간이 더 있었다면 무엇을 먼저 했겠나, 왜?" |
- 질문 전제가 실제 구현과 다를 수 있는 지점도 1개 포함한다(서술형에서 전제 오류를 지적하고 내 작업을 설명해야 하는 상황 대비).

## 답변 골격 (질문마다 3줄, 완성 답안 금지)
- 핵심 사실(근거 위치)
- 약점/위험과 영향
- 다음 검증·개선 방안

## 사용자 숙지 방식
1. `docs/COGNITION.md`의 "예상 후속 질문"에 질문 + 골격을 추가한다.
2. 사용자에게 가장 약한 3문항을 골라 **직접 말로/타이핑으로 답해 보도록** 요청하고 피드백한다($cognition-check 4단계 방식).
3. 숫자·파일명·결정 ID 같은 "외워야 할 앵커" 10개를 마지막에 목록으로 준다.

## 규칙
- 사실이 아닌 것을 강점으로 포장하지 않는다. 약점은 약점대로 정리하는 것이 서술형 대응의 핵심이다.
